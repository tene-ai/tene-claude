## 한 장 요약

### 구현의 세 기둥

| 기둥 | 수단 | 이유 |
|---|---|---|
| **절차 강제** | Hooks + Task `blockedBy` + 게이트 | CLAUDE.md 는 권고. 훅만이 결정론적 차단을 한다 |
| **의도 보존·검증** | Skills + Dynamic Workflow + 문서 | 의도는 대화에서 나와 문서에 남고 워크플로가 검증한다 |
| **결정론적 사실** | 경량 Node 스크립트 5종 | LLM 이 JSON 을 손편집하면 깨진다 |

### 로드맵

```
M0 스캐폴딩 → M1 문서 → M2 사이클 → M3 이해계층 → M4 루프 → M5 QA게이트 → M6 회고 → M8 배포
                                                                    M7 시크릿 (M2 후 병렬)
```

| M | 완료 조건 (실측) |
|---|---|
| M0 | `plugin validate --strict` 통과, 설치 성공 |
| M1 | 빈 프로젝트에서 sprint 폴더 + PRD 스캐폴드 생성 |
| M2 | 세션 종료 후 새 세션에서 "이어서" 동작 |
| M3 | 4계층·6질문 표가 실제 코드에서 자동 생성 |
| M4 | 의도적 미구현 AC 를 검출하고 개선 태스크 생성 |
| M5 | blocking AC 미충족 시 report 진입 차단 |
| M6 | 회고 R1~R6 이 사람 개입 최소로 완성 |
| M7 | 가드 시나리오 V1~V12 통과 |
| M8 | 외부 프로젝트에서 설치 → 전 사이클 완주 |

**M3 이 최대 위험 구간**이다. 인덱서 정확도가 M4~M6 산출물의 신뢰도를 좌우한다.

### Dogfooding 전환

**M2 완료 직후부터 M3 이후 개발은 tene 사이클로 진행한다.** 자기 도구로 자기를 만들지 못하면 출시하지 않는다.

### 기술 스택

| 항목 | 선택 | 근거 |
|---|---|---|
| 런타임 | Node.js 20+ | Claude Code 요구와 정렬, 추가 설치 불필요 |
| 외부 의존 | **0개** | CI 로 강제 (`assert-no-deps.js`) |
| 언어 | ESM JavaScript + JSDoc | 빌드 산출물 없음 (소스가 곧 배포물) |
| 테스트 | `node:test` | 표준 라이브러리 |
| 상태 | JSON / NDJSON | git diff·수동 편집 가능 |

### 검증 4층

```
V4 Acceptance   외부 프로젝트 전 사이클 완주
V3 Dogfooding   tene 로 tene 개발
V2 Eval         스킬·에이전트 판단 품질 (정직성 5종 100% 필수)
V1 Unit         lib/ 결정론적 동작 (가드 매트릭스 240 케이스)
```

### 최상위 3대 리스크

| ID | 리스크 | 방어 |
|---|---|---|
| **R-01** | 인덱서 정확도 부족 | M3 에서 조기 측정. 70% 미달 시 즉시 축소 |
| **R-11** | 문서 의식화 (문서는 통과, 코드는 불일치) | 미귀속 변경 검사 + 독립 판정자 |
| **R-21** | 시크릿 컨텍스트 유입 | fail-closed 가드. 여기만은 타협하지 않는다 |

### 축소해도 지켜야 하는 4가지

```
1. 4계층 + 6질문 절차        ← 기술부채 방어의 본체
2. blocking AC 게이트         ← spec driven 강제의 본체
3. insufficient 정직 표기     ← 신뢰의 본체
4. 시크릿 경계 (fail-closed)  ← 안전의 본체
```

## 착수 순서

```
1. W-01~W-07  (M0)   저장소 골격 + 매니페스트 + CI
2. W-05       공통   lib/util — 모든 스크립트의 전제
3. W-21,W-22  선행   상태 스키마 + 원자적 저장소 ← 병목
4. W-11~W-19  (M1)   문서 시스템
5. W-31~W-37  선행   인덱서 ← 병목
6. 이후 WBS 의존 그래프를 따른다
```

**두 병목**: `W-22 (상태 저장소)`, `W-37 (인덱스 빌더)`. 이 둘이 하위 작업 대부분의 선행이므로 우선 착수한다.
