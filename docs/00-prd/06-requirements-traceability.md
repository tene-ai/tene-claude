## 5. 문서 구성 (최종)

## 6. 남은 미결정 사항 (사용자 결정 필요)

01 §10의 D1~D7에 더해, 명세를 쓰면서 새로 드러난 것:

| # | 항목 | 선택지 | 기본 제안 |
|---|---|---|---|
| **D8** | 일치율 가중치 | AC 균등 / 심각도 가중 | **균등** (단순·설명가능. 심각도는 통과 여부로만 반영) |
| **D9** | AC 앵커링 시점 | design 자동 / do 이후 실측 / 혼합 | **혼합** — design에서 예상 앵커, do 이후 실측으로 교정 |
| **D10** | 문서 언어 | 항상 한국어 / 사용자 언어 감지 | **감지, 최초 sprint에서 확정 후 고정** |
| **D11** | check 실패가 상한 도달 시 | 강제 정지 / 사용자 승인 후 qa 진행 | **사용자 승인 후 진행** (잔여 갭은 R6로 이월) |
| **D12** | 워크플로 사용 기준 | 항상 / AC 8개 이상일 때 / 사용자 요청 시 | **AC 8개 이상 또는 명시 요청** (비용 고려) |
| **D13** | 자체 인덱서 지원 언어 1차 범위 | ts/js만 / +py,go / 전부 | **ts/js/py/go 4종 우선**, 나머지는 Tier 3 폴백 |

## 7. 스코프에 없는 것 (명시적 제외)

요구사항에 없어 다루지 않은 것들. 나중에 "왜 없지?"를 방지하기 위해 남긴다.

- 팀 협업 동시성 제어 (여러 사람이 같은 sprint를 동시에 진행) — 낙관적 잠금만 제공
- 원격 대시보드 / 웹 UI
- sprint 간 자동 의존 추론 (사람이 master plan에 선언)
- 요구사항 변경 이력의 diff 시각화
- 다중 저장소(모노레포 아닌) 교차 sprint
- 실시간 협업 알림 (Slack 등)
